A trustless decentralized VPN & paid agent API,
settled on Stellar.

dmesh connects clients and nodes with no party having to trust each other. Every payment is enforced by an on-chain Soroban contract using allowances you approve. The platform never holds your money and there is no dmesh token — you pay with real Stellar assets, including native XLM.

Built to remove trust, not just servers

Money cannot move unless both sides authorize it, and the rules are immutable contract code — not a database an operator can edit.

◇

No dmesh token, ever

Settle in real Stellar assets — native XLM or virtually any Stellar coin/token. You choose the asset in the UI. There is no protocol token to buy, hold, or trust.

⛨

Fully non-custodial

No treasury wallet, no server-held balances. The contract holds no funds; it only enforces settlement. Payments are pulled via transfer_from from an allowance you approve.

⌗

Contract-enforced fee

The 20% protocol fee is hard-coded in the contract and routed directly to the protocol address. Prices and tiers live in contract storage; every change emits an auditable event.

⇄

Dual-party authorization

A node cannot confirm counters the client did not propose, and a client cannot use 3 GB while paying for 1. Replay of a settled session is rejected on chain.

⏱

Crash-safe by design

Sessions carry a TTL. If a node or client disappears, the session simply expires. A session that is never confirmed never moves any funds — no accidental charges.

◎

Identity is just a key

Nodes register with a locally generated Stellar address. No email, name, or country is collected from them. Geo/IP type is resolved server-side from a CI-refreshed database — clients are never trusted.

How a settlement works

Each step is a Stellar transaction signed by the party it belongs to. The coordinator only relays; it cannot spend.

Approve an allowance

The client approves a spending cap on the token's Stellar Asset Contract. Funds stay in the client's wallet; nothing is deposited to dmesh.

Open a metered session

Client and node open an on-chain session bound to a nonce, tier and TTL. Traffic is metered with an anti-fraud bandwidth ceiling.

Propose, then confirm

The client proposes the counters; the node confirms matching counters. Mismatched or replayed confirmations are rejected by the contract.

Atomic split on chain

The contract pulls exactly the agreed amount via transfer_from: 80% to the node, 20% protocol fee — in a single atomic transaction.

Transparent, on-chain pricing

Rates are stored in the contract and served live from the network. The same values power every settlement.

Protocol fee is fixed at 2000 basis points (20%) in contract code. The asset's on-chain oracle price determines the exact token amount per GB.

No-trust security model

“Use it and leave without paying” is not possible. Settlement is bounded by the client's approved allowance and the agreed counters; a node is paid only for counters the client proposed and the contract confirms. Unconfirmed sessions expire and charge nothing beyond network resource fees.
“A node fakes traffic” is not possible. The contract only accepts a confirmation that matches the client's proposal. Fabricated or inflated counters fail authorization, and every settled session is protected against replay.
